# First release and target acceptance

Target edition: 17 October 2026. These public-door journeys match every named clause in [CONTRACT.md](CONTRACT.md). Status rows change with the implementation and named public-door coverage in the same commit; they describe checked behavior, not future promises. Published journeys keep the first-release behavior. New clauses describe the full switching destination, including built-in trust accounting and provider operations; the old “not needed” exclusions no longer define the target.

Build the app with `pnpm run build` before running focused practice journeys with `pnpm run test:satchel`; build the run site with `pnpm run build:site` before `pnpm run test:site`. CI is the full verification wall. Existing public API flow coverage is in `tests/satchel/flows.test.mjs`; static site traversal is in `tests/site/navigation.test.mjs`. A future journey is not claimed passing because it is listed here. Fakes are allowed only at paid/network edges, with real application routes, permission checks and persisted state throughout.

Use a US firm with lawyers, assistants, billing and trust staff plus client/payer identities. Examples are journey inputs only. For provider work use authorized test accounts or official sandboxes and retain source references, requests, replies and reconciled end states. At 1440 and 390 pixels exercise all changed screens with populated records; native mobile obligations also need actual supported app journeys. Agent approval, legal judgment and trust authority are always tested separately from preparation.
